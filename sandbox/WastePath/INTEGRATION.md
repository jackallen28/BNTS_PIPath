# Later PiPath integration

WastePath is a standalone test program; the main PiPath application is unchanged.

- `vision.py`: uploaded ML Camera background subtraction and 29 colour/shape
  measurements. Uses the full image and largest changed contour.
- `model.py`: original-style group scaling, distance-weighted five-neighbour voting,
  leave-one-photo-out quiz, novelty threshold and .5 smoothing. Only two classes:
  Waste and Recycling. Requires ten photos per class, without group requirements.
- `camera.py`: newest-frame USB reader and synthetic demo; preserves 4:3 proportions.
- `storage.py`: version 2 full-frame measurements, validated numeric NPZ loading and
  atomic saves. Old cropped data is backed up before new training replaces it.
- `outputs.py`: configurable servo/LED outputs and independent decision watchdog.
  `update(label, rejected=False)` sends an accepted category; an unknown item uses
  `update(None, rejected=True)` to flash configured LEDs without opening a servo.
  Empty scene/camera loss uses `update(None)` to stop the LED and request servo rest.
- `app.py` / `output_ui.py`: Tk workshop, settings and the original-style photo flow.

For a later merge, move the workshop into a PiPath kept screen and use its theme,
TitleBar and PButton controls. Give the screen ownership of the camera and output
controller. Only send fresh Live results to GPIO; disarm when the screen is hidden,
settings/training change or the app closes. Do not restore the armed state from disk.
The synthetic demo cannot enable hardware, and the optional Test screen never does.
Keep training and test records separate and use a project-owned data directory.

The original extraction and kNN code were adapted from the user-provided
`rpi-ml-camera.zip`. Regression fixture measurements/votes were generated by running
that uploaded original with its object names changed to Waste/Recycling only.
No classifier is trained to recognise people, and no position/safety feedback is
provided by the servo controller.
